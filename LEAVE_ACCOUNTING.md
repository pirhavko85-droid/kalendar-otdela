# Единый учёт отпусков — решение 11.11.2026

Эти правила заменяют прежние ручные остатки. Мастер — `События`. Лист `Отпуска` содержит FILTER-представление мастера; второе списание из него недопустимо. `Нормы отпусков` содержит нормы и признак полноты истории по сотруднику/году. Колонки K:M справочника сотрудников теперь производные формулы.

## Поля мастера

Существующие A:U сохранены. Добавлены V:AF:

| Колонка | Поле модели | Значение |
|---|---|---|
| V | leaveYear | Год, из нормы которого списывается отпуск |
| W | leaveDays | Списываемые сутки отпуска |
| X | travelDays | Дорога отдельно, 0–5, не для ВБД |
| Y | holidayBonusDays | Один дополнительный день ФГГС на часть с официальным праздником |
| Z | totalAbsenceDays | Фактический интервал включительно |
| AA | partNumber | Номер части внутри отпускного года/категории |
| AB | destination | Место следования, если известно |
| AC | travelBasis | Основание дороги, если известно |
| AD | officialHolidayCount | Праздников в основной части |
| AE | baseEnd | Окончание основной части до дополнительного дня |
| AF | leaveType | Вид отпуска |

G для отпусков — совместимое отображение W (`=WномерСтроки`), не второй источник. Для остальных событий G работает как раньше. U «Когда изменено» экспортируется как modifiedAt/updatedAt. S «Даты продления отпуска» сохранена для совместимости; новый снимок выводит дополнительную дату из основной модели, а обработчик обновляет S при записи.

## Расчёт

Норма минус записи со статусом **Факт** по явному leaveYear — фактический остаток. План уменьшает только прогноз. Дата начала сама не превращает план в факт. Отмена исключает запись; уникальный ID предотвращает повторное списание. Переходящий январь принадлежит тому же отпускному году, а графики показывают календарные даты. Летний и основной отпуск списывают одну норму; ВБД — отдельную.

Период отсутствия = списываемые сутки + дорога + дополнительный день. Несогласованные даты не публикуются как корректные. При ошибке записи клиент не показывает вымышленный точный остаток. Для неполной истории показываются известные факты без утверждения точного остатка.

Дорога не считается ежегодным лимитом, автоматически не назначается. При повторном её предоставлении в одном году выводится предупреждение о проверке основания. Конкретные календарные даты дороги не выдумываются: если известно только число суток, оно показывается в подписи периода.

Для ФГГС официальный праздник отличается от обычного и перенесённого выходного. Один или несколько официальных праздников дают один дополнительный календарный день **на часть**, без переноса с субботы/воскресенья. Это утверждённая внутренняя модель проекта, а не заключение о применении трудового законодательства.

## Синхронизация и изменения

`tools/fetch-sheets.cjs` читает четыре основные вкладки и `Нормы отпусков`; `tools/build-snapshot.cjs` собирает и проверяет снимок, затем шифрует. Удаление вкладки норм после перехода на новую модель блокирует публикацию вместо возврата к ручным остаткам. Расшифрованные данные и ключи остаются в private/, в Git попадает только data.enc.json.

Расчёты сайта и проверка сервера используют один `leave-accounting.js`. В `tools/event-writer/Code.gs` размещена его копия между GENERATED-маркерами; тест проверяет совпадение. После изменения серверного кода нужно обновить существующее развёртывание Apps Script, сохранив endpoint и права доступа.

Обычная карточка отпуска принимает списываемые дни и дорогу, рассчитывает окончание с учётом бонуса. Общий редактор позволяет явно менять поля: конечный период и сумма должны совпадать. Автор — заявленная подпись, без новой Google-авторизации.

## Проверка и восстановление

Перед миграцией читать актуальные диапазоны и делать нативную копию всей таблицы плюс локальный резервный снимок. Менять записи по ID, сохранять журнал «было/стало». Не запускать повторно исторические одноразовые запросы миграции. Нормализация модели идемпотентна: повторное построение из того же источника не добавляет дни и не создаёт ID.

Проверки: `node tools/check.cjs`, `node --test tools/*.test.cjs`. Для мобильной проверки локально доступна `/preview-mobile.html` с рамкой 390×844; в публикацию GitHub Pages эта служебная страница не включается.

Производственный календарь проверен для пятидневной недели 2025–2027. Переносы 2028 года не утверждаются автоматически; интерфейс предупреждает об этом. Внутреннее правило «один бонус на часть» требует отдельной юридической сверки со статьёй 120 ТК РФ, исключающей нерабочие праздничные дни из календарных дней ежегодного оплачиваемого отпуска.
