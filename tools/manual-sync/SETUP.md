# Ручная синхронизация отдела

Черновик от 05.11.2026. До развёртывания и проверки на действующем сайте функция не включена.

Google Apps Script проверяет Google-аккаунт оператора и запускает только `sync-data.yml` ветки `main` репозитория `pirhavko85-droid/kalendar-otdela`. Разрешены Роман, Юлия и Павел. Редактировать код скрипта могут только владелец и назначенные им разработчики; операторам выдаётся только URL web app.

Проект Google Apps Script создан:

## Подготовка и публикация

1. В проекте сохранить `Code.gs` и `Page.html` из этой папки. Манифест — `appsscript.json`: режим `USER_ACCESSING`, доступ `ANYONE` (только вошедшие в Google), scopes только email и внешний HTTP-запрос. Режим «выполнять от имени владельца» не подходит: нельзя подменять личность оператора владельцем.
2. Создать отдельный fine-grained GitHub token: владелец pirhavko85-droid, только репозиторий kalendar-otdela, Actions Read and write, Metadata Read (автоматически). Без Contents write, Administration, Secrets и доступа к другим репозиториям. Ограничить срок действия и записать дату замены в личной памятке.
3. Токен сохранить только в Script Properties проекта под именем `GITHUB_ACTIONS_TOKEN`. Не в исходнике, HTML, Git, документах операторам, параметрах URL или браузерном localStorage. Не использовать существующий широкий Git credential ноутбука.
4. Опубликовать изменения `sync-data.yml` с необязательным `request_id`. Старые ручные и плановые запуски продолжают работать без этого параметра.
5. Развернуть версию web app с режимами выше. Первый запуск требует согласия каждого пользователя на доступ к email и выполнение внешнего запроса. Не требует доступа к Google-таблицам/Диску от этого нового скрипта: чтение делает существующий workflow своим служебным аккаунтом.
6. Проверить запрет постороннему/пустому аккаунту, один реальный ручной запуск, корректное ожидание публикации, отсутствие параллельного запуска по повторному нажатию, ошибку при недействительном токене.
7. Подставить полученный публичный URL `/macros/s/.../exec` в `MANUAL_SYNC_URL` в `index.html`. Пока адрес пуст, новая кнопка скрыта. Обновить APP_VERSION, подпись версии и версию кэша `sw.js`; проверить мобильный и настольный вид, затем опубликовать.

## Пользовательский путь

В дашборде открыть «Импорт / экспорт» → «Синхронизировать с Google-таблицей». Откроется защищённая страница Google: оператор подтверждает аккаунт, нажимает запуск и видит очередь, чтение, публикацию и итог. После завершения возвращается в дашборд и нажимает «Получить свежие данные». Первый вход каждого оператора требует его собственного подтверждения Google.

Процесс работает при выключенном ноутбуке. Общий ключ отдела нужен для просмотра снимка, но не является разрешением запуска. Новые операторы получают право запуска только после явного изменения списка `SYNC_ALLOWED` владельцем. Доступ к редактированию таблицы остаётся отдельным разрешением Google.

## Проверки и сопровождение

`node --test tools/manual-sync.test.cjs` — отказ чужому аккаунту/просроченному сеансу, точный workflow и main, объединение повторных запросов, привязка статуса к уникальному request_id, обработка ошибок. Затем `node tools/check.cjs` и живая проверка развёрнутого сервиса.

Страница не объявляет публикацию успешной по одному ответу dispatch: ожидает итог всего workflow, включая Pages. Результаты не содержат токенов, данных таблицы или ключей. Повторный запуск ограничен глобальной блокировкой и минутным интервалом. Срок ожидания появления запуска — 15 минут.

При смене GitHub token обновить только Script Properties. При отзыве доступа оператора обновить и Google sharing, и список допуска скрипта. Не делиться доступом к редактору скрипта: Script Properties доступны коду проекта.
