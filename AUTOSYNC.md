# Фоновое обновление: настройка и продолжение

Решения Романа от 01.11.2026:
- Основная база — Google Sheets. Код дашборда редактирует только Роман.
- Будущие операторы получают доступ только к данным таблицы, не к GitHub.
- Сейчас никому новые права не выдаются.
- Часовой пояс — Москва. Пн–Пт 09:00–17:55 проверка каждые 5 минут;
  каждый день 18:00, 00:00, 06:00; Сб–Вс дополнительно 12:00.
- Сайт публикуется только при изменении содержимого или метаданных источника.
  Само расписание GitHub допускает задержки и не гарантирует интервал ровно 5 минут.

## Что подготовлено

`.github/workflows/sync-data.yml` читает таблицу, проверяет согласованность
чтения по modifiedTime до/после, строит проверенный AES-GCM снимок, коммитит
реальные изменения и явно вызывает публикацию. Обычный push от GITHUB_TOKEN
не запускает другой push-workflow, поэтому публикация вызвана через workflow_call.
Исходный сайт продолжает работать, даже если чтение или проверка не удались.
Временные открытые данные и ключ находятся только в RUNNER_TEMP и удаляются.
Сайт собирается только из разрешённых файлов, без служебных документов и секретов.

Изменения сохраняются при реальной правке, а не на каждой проверке.
Дополнительно раз в календарный месяц после успешной проверки сохраняется
`.github/sync-health.json` — реальная техническая отметка проверки доступа
и валидации снимка. Она создаёт изменение репозитория и позволяет контролировать
работу при отсутствии пользовательских правок. Пустые запуски сами по себе
не являются надёжной защитой от отключения расписания через 60 дней.
Если уже отключено, расписание надо включить вручную.

## Инструкция для повторной настройки

Настроить в Google Cloud:
1. Выбрать проект; включить Google Sheets API, Google Drive API, IAM Credentials API.
2. Создать отдельный service account только для чтения календаря.
3. Дать этому адресу роль «Читатель» только в таблице
   https://docs.google.com/spreadsheets/d/1q83XSPLXRd9Fgk20gSs601SX9LZWA1yQvkZQQEQ49KU/edit
4. Для получения токенов через google-github-actions/auth дать service account
   роль Service Account Token Creator на самого себя (не роль на все ресурсы проекта).
5. Сохранить JSON credentials служебного аккаунта в GitHub Actions secret
   SHEETS_SERVICE_ACCOUNT_JSON. Не прикладывать credentials в чат или Git.
6. Существующий общий ключ в формате JSON сохранить в secret
   DASHBOARD_SHARED_KEY_JSON. Ключ отдела не менять.

Альтернатива для последующего усиления — Workload Identity Federation вместо
долгоживущего JSON-ключа. Это требует отдельной настройки доверия GitHub↔Google.

После публикации кода настроить variable AUTO_SYNC_ENABLED=true в репозитории,
запустить Sync Google Sheets вручную и проверить успешность обоих этапов,
реальную дату таблицы, редактора и получение версии с телефона. До этой проверки
не считать фоновую синхронизацию включённой.

## Версия данных

В зашифрованный снимок входят hash содержимого, modifiedTime таблицы,
имя последнего редактора (если Google его сообщил) и время сборки снимка.
В интерфейсе эти значения отделены от времени загрузки на устройство.
Это метаданные всей таблицы, не журнал каждой изменённой ячейки. Для нескольких
операторов понадобится дополнительно журнал с ID записи, временем и автором;
не выдавать имя ChatGPT/служебного аккаунта за достоверное имя человека.

## Лимиты

Использовать стандартный ubuntu-latest в публичном репозитории, без платных
larger runners. По текущим правилам GitHub такое выполнение бесплатно.
Если репозиторий станет приватным, заново проверить квоты: текущий режим
даёт примерно 8640–8928 коротких запусков в месяц и может превысить бесплатные
минуты приватного репозитория. Публикаций гораздо меньше — только при изменениях.
Не накапливать артефакты исходных таблиц. В случае лимитов/ошибок сохранять
последний корректный снимок; не заменять данные пустой базой.
