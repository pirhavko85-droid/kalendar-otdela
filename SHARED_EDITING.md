Мероприятия не меняют локальную db до записи и не используют старую очередь collaboration.js. При запуске прежние операции мероприятий переносятся в неподтверждённые черновики с исходным requestId; оригинал очереди сохраняется в departmentLegacyMeetingBackupV2. Старые блокировки мероприятий снимаются, другие коллекции сохраняются. Новая карточка остаётся доступной независимо от фонового обновления. Повтор запроса идемпотентен. Черновик убирается только после сверки фактически опубликованного расшифрованного снимка.

Сервер сверяет исходные значения перед записью, отклоняет конфликт, проверяет результат чтением. При частичной ошибке восстанавливает значения, формулы и форматы всей группы. Резерв больших групп разбит на части по размеру UTF-8, чтобы не превышать лимит Script Properties. Время мероприятий записывается текстом, без изменения форматов отпусков.

После записи запускается существующий workflow публикации. Резервное расписание: круглосуточно каждые пять минут. Сборщик повторяет временные сетевые ошибки/HTTP 429 и 5xx; отказ в доступе не повторяет. Проверка стабильности ревизии и защита старого снимка сохраняются. GitHub/Google могут задерживать доставку; подтверждение записи и публикация — разные этапы.

Проверки: node tools/check.cjs; node --test tools/*.test.cjs. Полный автоматический цикл для всех семи авторов, изменение участников/дат, повтор, конфликты, откат и миграция старой очереди. Реальный цикл: Павел → добавление двух участников; Юлия → переименование, 19–20.11, 23:50, три участника; Роман → отмена всех трёх строк. Собственная техническая запись отменена. По запросу Романа отменены обе строки «Тест7». Другие тесты не удалялись. Проверен анонимный POST без cookies/Google-входа на повторе отмены технической записи.
