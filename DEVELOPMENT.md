# Работа над календарём отдела

## Запуск

Дважды нажмите `start-dashboard.cmd`, оставьте окно открытым и откройте
http://127.0.0.1:4173 в браузере. Закрытие окна остановит сервер.
Из терминала: `npm start`. Установка пакетов не требуется.
Проверка синтаксиса: `npm run check`.

## Исходная версия

Перенесена история https://github.com/pirhavko85-droid/kalendar-otdela
до коммита 7b8e1d2965307d06da575e79a98d84135af888e2 (версия 1.11.9).
Исходная версия отмечена локальной меткой `baseline/v1.11.9`.
Рабочая ветка: `codex/local-setup`. Перенос не меняет опубликованный сайт.

## Файлы

- `index.html` — интерфейс, стили, расчёты, локальное хранение, импорт и экспорт.
- `data.enc.json` — опубликованный зашифрованный снимок данных.
- `sw.js`, `manifest.json` — кэширование и установка веб-приложения.
- `.github/workflows/pages.yml` — публикация GitHub Pages при изменении `main`.
- `tools/` — локальный сервер и проверка синтаксиса, без внешних зависимостей.

## Как сейчас работают данные

Редактор — Роман; отдел просматривает результат и предлагает изменения.
Редактирование в интерфейсе сохраняется в localStorage текущего браузера.
Локальный адрес и опубликованный сайт имеют отдельные хранилища.
Для переноса ручных правок используйте существующий экспорт/импорт JSON.

При подключённом общем ключе приложение загружает `data.enc.json`,
расшифровывает его, сохраняет резервную копию в `kalendarOtdelaPreSyncBackupV1`
и сохраняет локальные записи с ID, которых нет в снимке. Это происходит и при старте.
Для совпадающих ID приоритет имеет снимок; локальное изменение такой записи
может быть перезаписано. Перед обновлением следует экспортировать ручные правки.
Сам ключ остаётся вне репозитория; он не скопирован из Downloads.

Загрузка снимка — односторонняя. Кнопки записи данных на GitHub в приложении нет.
Добавлена команда `tools/build-snapshot.cjs` для формирования снимка из результатов
чтения Google Sheets. Автоматического фонового обновления Google → GitHub нет.
Изменения передаются в Google Sheets через подключённый инструмент в чате,
затем читаются обратно, собираются в снимок и публикуются отдельным шагом.

## Основная база и обновление (подтверждено 01.11.2026)

Основная база: https://docs.google.com/spreadsheets/d/1q83XSPLXRd9Fgk20gSs601SX9LZWA1yQvkZQQEQ49KU/edit
Google-таблица — источник данных; GitHub — код и зашифрованный снимок для просмотра.
Тестовые записи сохраняются до отдельного решения пользователя.

Порядок обновления:
1. Прочитать метаданные и нужные диапазоны таблицы через Google Drive/Sheets.
2. Прочитать листы «Сотрудники», «События», «Дни рождения», «Задачи» с заголовками.
   Сохранить значения в игнорируемый файл `private/drive-audit.json` формата
   `{ "Сотрудники": [...строки], "События": [...строки], "Дни рождения": [...строки], "Задачи": [...строки] }`.
   Диапазоны должны покрывать все записи, включая строки после пустых строк.
3. Выполнить:
   `node tools/build-snapshot.cjs --source private/drive-audit.json --key <путь-к-ключу> --out private/new-data.enc.json`
4. Проверить количества и расхождения. Команда отказывается молча удалять записи,
   проверяет заголовки, даты, уникальность ID и расшифровку результата.
5. Сохранить предыдущий снимок, заменить `data.enc.json` проверенным результатом.
6. Проверить локальную синхронизацию и вкладки; сохранить Git-коммит.
7. Опубликовать в `main`, дождаться успешного GitHub Pages и проверить сайт.

Ключ и расшифрованные материалы находятся вне отслеживаемых файлов.
`private/` исключён из Git и недоступен через локальный сервер.
Проверки синтаксиса, расшифровки и открытия мобильных вкладок выполнены.
В оригинальном коде шапка показывает 1.11.9, а APP_VERSION равен 1.11.8 —
это расхождение пришло из GitHub, интерфейс при восстановлении не менялся.

## Ближайшие этапы

1. Проверить локальную версию с данными через существующий импорт или общий ключ.
2. Настроить понятный путь: редактирование → резервная копия → общий снимок → публикация.
3. Выбрать первый блок изменений по замечаниям отдела.
4. Постепенно разделять большой index.html при доработках.

Каждый законченный этап проверять и сохранять в Git. Публикацию выполнять
отдельным явным шагом после проверки результата.
